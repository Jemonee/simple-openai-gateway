# OpenAI 网关控制台 v0.1.1 版本升级说明

- 发布日期：2026-08-13
- 发布类型：功能与稳定性更新
- 升级版本：`v0.1.0` -> `v0.1.1`

## 1. 版本概述

`v0.1.1` 在保持 OpenAI 兼容接口和现有项目配置方式不变的基础上，补充渠道验证、网页对话、资源追踪及会话观测能力，并完善路由容错、费用统计、运行时配置和管理控制台体验。

本版本会在应用启动时通过 GORM 自动迁移 SQLite 表结构，并对部分历史数据执行回填和纠偏。升级前应停止旧版本进程并完整备份数据库文件；源码构建仍要求 Go `1.25.4`、Node.js `^20.19.0 || >=22.12.0` 和 pnpm `10.23.0`。高档模型指纹验证默认使用内嵌的 Node.js Native Codex 传输脚本；运行主机找不到 `node` 命令时，自动回退到纯 Go 传输实现。

## 2. 新增功能

### 2.1 GPT-5.6 模型指纹验证

- 新增渠道验证页面及验证会话管理接口，可对申报为 `gpt-5.6-sol`、`gpt-5.6-terra` 或 `gpt-5.6-luna` 的已启用映射执行模型行为验证。
- 提供低、中、高三个检测档位，分别固定为 14、64、202 个逻辑任务；检测过程采用 8 路并发，每个逻辑任务最多执行 3 次 HTTP 尝试。
- 综合 Juice 型号指纹、固定输出完整性、显式覆盖检查和相对行为指纹生成七类结论，并展示各参考模型的匹配度及技术证据。匹配度表示相对于冻结基线的行为相似度，不代表真实路由概率。
- 验证采用持久化异步任务，支持进度查询、主动停止和应用重启后恢复；逻辑任务、HTTP 重试、Token、费用以及请求与响应正文均可追溯。
- 验证明细不保存渠道 API Key；单次请求或响应正文最多在 SQLite 中保留 128 KiB，超出部分标记为截断，相关证据受调用明细保留策略影响。
- 高档验证优先使用 Node.js Native Codex 传输；未检测到 Node.js 时会显著提示纯 Go 回退，并在验证会话及每次 HTTP 尝试中记录实际传输实现。

### 2.2 网页对话

- 新增网页对话页面，可在管理控制台内选择公开模型和指定渠道发起对话。
- 展示实际命中的渠道、上游模型、Token 用量和估算费用，便于完成配置后的快速连通性检查。

### 2.3 资源中心

- 新增请求资源识别和资源中心，汇总请求中的 URL、文件、图片及其他可识别资源，并关联来源会话与请求记录。
- 支持按资源类型、敏感标记、关键字和最后发现时间筛选；提供受限的浏览器预览及敏感资源标记。

### 2.4 会话与运行观测

- 增强 Codex、Copilot 及其他客户端的活动会话识别，补充父子会话关系、会话来源、上下文窗口和压缩状态观测。
- 新增渠道模型每日统计，并在调用日志、会话日志和路由详情中补充费用、缓存、阶段耗时、路由原因及资源关联信息。
- 新增调用明细自动保留策略，保留期可设为永不清理、7 天、15 天或 30 天；手动正文清理支持按天数选择，并继续保留状态、Token、费用和耗时统计。
- 新增历史调用完整删除能力，可同时删除调用日志、路由尝试、阶段耗时和资源引用。该操作不可恢复，与仅清理请求及响应正文的操作不同。

### 2.5 控制台体验

- 管理控制台支持跟随系统深色主题，并为活动会话和会话日志提供常用菜单快捷入口。
- 活动会话来源筛选改为可切换标签，并保证至少保留一个来源条件。
- 设置页支持在保存前恢复表单；资源、渠道验证和网页对话均已注册为可直接访问的功能菜单。

## 3. 修复问题

- 修复渠道热力图在部分数据分布下显示不准确的问题。
- 修复失败请求参与费用倍率基准计算的问题，避免异常调用影响后续成本评估。
- 修复不同页面费用展示精度不一致的问题，统一按六位小数进行四舍五入。
- 修复响应头超时配置仅在进程启动时生效的问题；保存配置后，新建上游请求会使用最新超时值。
- 修复浏览器上下文场景下会话标题提取不准确的问题。
- 修复路由计划生成后渠道被停用、映射被停用或渠道进入熔断时仍可能继续请求该候选的问题；转发前会重新校验候选状态并选择其他可用渠道。
- 修复上游返回 HTTP `403` 且错误码为 `model_not_allowed` 时不会切换候选渠道的问题；其他普通 `403` 错误仍保持原有处理方式。

## 4. 优化内容

- 当公开模型仅有一个可用映射时，直接生成确定性路由结果，不再加载无必要的统计指标或执行随机抽样。
- 完善流式及非流式响应的失败识别、DNS 错误记录、应用级错误分类、重试原因和熔断状态记录，提升故障定位的一致性。
- 完善响应阶段耗时、缓存 Token、取消请求用量和上游费用来源的记录规则，避免取消或失败调用被计入可计费成功量。
- 优化资源、调用和会话数据的关联查询及历史明细清理，减少失去请求引用的辅助会话记录残留。
- 优化跨平台构建脚本，增加前端构建失败日志和各阶段耗时输出，同时保留按分支或 `PACKAGE_NAME` 生成产物名的规则。
- 统一管理控制台为“红粉”主题变量体系，改善桌面端与窄屏布局、状态反馈、代码查看和会话详情的可读性。

## 5. 兼容性与升级影响

### 5.1 管理接口变化

`v0.1.1` 新增以下异步渠道验证管理接口：

- `POST /api/admin/gateway/verifications`：创建验证任务，成功时返回 `202 Accepted` 和 `VerificationSession`。
- `GET /api/admin/gateway/verification-sessions`：查询验证会话及运行进度。
- `GET /api/admin/gateway/verification-sessions/:id`：查询会话及 HTTP 尝试明细。
- `GET /api/admin/gateway/verifications` 与 `GET /api/admin/gateway/verifications/:id`：查询已生成的验证报告。
- `POST /api/admin/gateway/verification-sessions/:id/stop`：请求停止运行中的验证会话。

直接调用上述新增接口的客户端应按异步任务处理，并识别 `running`、`stopping`、`completed`、`stopped`、`failed` 会话状态。若客户端曾接入早期 `v0.1.1` 开发快照中同步返回 `201 Created` 和 `VerificationReport` 的临时接口，升级后必须适配当前异步协议。OpenAI 兼容的 `/v1/*` 客户端接口未因本次升级改变请求格式。

### 5.2 数据库变化

- 新增验证任务、资源关联、渠道模型每日统计、会话关系及上下文观测相关表和字段。
- 应用首次启动时会自动迁移表结构，并回填或纠偏渠道模型每日统计、父子会话、上下文窗口、压缩次数以及部分历史结果、费用和 Token 数据，不需要手工运行迁移脚本。该过程会读写历史记录；数据量较大时可能持续较长时间并增加 SQLite WAL 文件体积。
- 迁移期间不得启动新旧版本并发访问同一数据库，也不应强制中断进程。迁移失败时应保留完整启动日志，在查明原因前停止重复启动。
- 不支持使用 `v0.1.0` 直接打开已迁移的数据库。回退时必须先停止 `v0.1.1`，恢复升级前的数据库及配置备份，再使用 `v0.1.0` 程序启动并完成基础请求验证。

### 5.3 默认配置变化

- 最大尝试次数、请求体上限和响应头超时的默认值分别调整为 1、256 MiB 和 15 秒。配置文件中缺少相应字段时采用新默认值；已显式保存的字段继续按原值加载。
- 新增调用明细自动保留配置。配置文件缺少该字段时默认采用永不清理；管理员可在系统设置中改为 7 天、15 天或 30 天。
- 升级后应在系统设置中复核最大尝试次数、请求体上限、响应头超时和数据保留策略，确认其符合当前运行要求。

## 6. 升级步骤

1. 正常停止正在运行的 `v0.1.0` 进程，确认没有进程继续访问 SQLite 数据库。
2. 完整备份 `data/data.db`、`.env` 和 `config/config.toml`。若存在 `data/data.db-wal` 或 `data/data.db-shm`，应将数据库及其辅助文件作为同一组备份；也可在停止服务前完成 SQLite checkpoint 后再备份。恢复时必须使用同一时间点的一组文件。
3. 获取 `v0.1.1` 源码或发布产物。应在原工作目录中运行新版本，保留原有 `data/`、`.env` 和 `config/config.toml`；不得以解压目录整体覆盖的方式遗漏或替换这些运行数据。源码构建时确认 Go、Node.js 和 pnpm 版本满足要求。
4. 使用锁文件安装依赖并完成前端构建：

   ```bash
   go mod download
   pnpm --dir frontend install --frozen-lockfile
   pnpm --dir frontend build
   ```

5. 启动 `v0.1.1` 并等待表结构迁移和历史数据回填完成。迁移期间不得中断进程，也不得同时运行新旧版本访问同一数据库文件；数据量较大时应预留足够的维护时间和磁盘空间。
6. 登录管理控制台，核对系统设置、渠道状态、公开模型映射、访问令牌和日志保留策略。
7. 发起测试请求并检查调用日志；高档模型指纹验证会优先使用运行主机上的 Node.js，未安装 Node.js 时自动回退到纯 Go 传输实现。

## 7. 升级后验证

建议至少完成以下检查：

- `GET /v1/models` 能返回当前令牌允许访问的模型。
- `POST /v1/chat/completions` 或 `POST /v1/responses` 的流式、非流式请求均可正常完成。
- 管理控制台可打开渠道管理、模型路由、渠道验证、网页对话、资源中心和系统设置页面。
- 调用日志可查看实际渠道、路由原因、Token、费用和响应阶段耗时。
- 多渠道模型在首选渠道停用或返回 `model_not_allowed` 时，可按配置切换到其他可用候选。

源码交付可执行以下命令进行完整验证：

```bash
go run ./tools/projectctl check
go test ./...
go vet ./...
go build -buildvcs=false ./...
pnpm --dir frontend build
```

## 8. 已知限制

- 当前仍面向单实例 SQLite 部署，不提供跨实例共享路由、限流、会话或验证任务状态。
- 流式响应仅能在首个有效输出前无感切换渠道；开始向客户端输出后发生中断时不会从其他渠道续传。
- 模型指纹结论用于辅助识别上游行为，不构成模型身份、服务质量或合规性的绝对证明；代理改写、参数过滤和探针拦截均可能影响结果。
- 高档模型指纹验证会产生较多上游调用、Token 消耗和费用，执行前应确认渠道额度及成本承受范围。
