# OpenAI 网关控制台 PC 端使用手册

> 适用版本：0.1.0
> 更新日期：2026-07-31
> 适用终端：PC 浏览器

本手册用于完成网关的首次接入、日常观察和故障处理。界面中的时间统一按东八区展示；渠道密钥、访问令牌和日志正文属于敏感信息，请仅向受信任的管理员开放控制台。

## 1. 登录与首次引导

打开控制台后，使用管理员账号登录。浏览器中没有引导完成记录时，系统会自动显示首次使用引导，依次介绍渠道、模型路由、访问令牌、本机配置、调用日志、活跃会话和系统设置。

- 点击“下一步”浏览完整引导。
- 点击某一步名称可直接查看该功能说明。
- 点击“跳过引导”或“开始使用”后，完成状态会保存在当前浏览器。
- 清除站点本地存储后，下次登录会再次出现引导。
- “一键配置本地文件”只会在通过 `localhost`、`127.0.0.1` 或其他回环地址访问运行机时出现。

## 2. 推荐的首次配置顺序

首次使用建议按以下顺序完成：

1. 在“渠道管理”中连接至少一个上游渠道。
2. 获取上游模型，并启用需要对外提供的模型映射。
3. 在“模型路由”中确认公开模型、候选渠道和调度策略。
4. 在“访问令牌”中签发客户端令牌并设置模型范围。
5. 在“运行总览”中复制客户端配置；本机访问时也可一键写入 Codex 配置文件。
6. 发起一次测试调用，并在“调用日志”中核对路由结果。

## 3. 配置渠道

进入“渠道管理”，点击“新增渠道”。

### 3.1 基本连接信息

填写渠道名称、OpenAI 兼容服务地址和上游 API Key。渠道名称应能区分供应商、区域或账号，例如“生产主渠道”或“备用渠道”。服务地址填写上游兼容接口的根地址，不要把具体模型名放入地址。

保存或执行模型获取前，确认运行机能够访问该地址。上游密钥保存后不会以完整明文重新显示。

### 3.2 获取和启用模型

使用模型获取功能读取上游模型列表。为需要对外提供的模型建立映射，并确认以下字段：

- 公开模型：客户端请求中使用的模型名称。
- 上游模型：实际发送给该渠道的模型名称。
- 优先级：数值较高的映射优先进入候选组。
- 权重：同优先级候选的基础调度权重。
- 价格与倍率：用于估算费用和价格评分。
- 启用状态：只有渠道和模型映射都启用时才可参与调度。

首次获取模型时，系统设置中的“首次渠道配置自动启用模型”会自动启用精确匹配的常用模型。其他模型需要管理员确认后再启用。

### 3.3 渠道状态

渠道停用后，其全部模型映射退出调度。渠道发生连续失败时可能进入临时熔断；严重的账号或凭据错误可能直接升级熔断等级。恢复或人工处理过程可在“熔断记录”中查看。

## 4. 查看和调整模型路由

进入“模型路由”查看公开模型列表。展开任一模型，可查看它的候选渠道、映射状态、上游模型、近期成功率、优先级、权重、价格和性能数据。

### 4.1 路由策略

- 优先级加权：先选择最高优先级组，再按价格、效率、质量、均衡和映射权重计算概率。
- 成本优先：放大渠道之间的价格优势，适合更重视费用的场景。
- 效率优先：放大首 Token、响应延迟和输出吞吐差异，适合交互响应敏感的场景。

路由不是固定轮询。除会话亲和或响应亲和外，系统会按每个候选的综合概率抽样。同一模型至少应保留一个可路由映射；生产环境建议准备不同渠道的备用映射。

### 4.2 路由决策占比

进入“系统设置”的“路由决策”区域。整条直线代表 100%，三个圆形分隔点把它划分为价格、效率、质量和均衡四段。

- 拖动分隔点时，只调整分隔点左右两项，合计始终保持 100%。
- 使用 Tab 聚焦分隔点后，可用方向键微调，Home/End 移到允许范围的两端。
- 也可直接输入任一项百分比，其他项会按当前比例自动分配。
- 质量占比最低为 5%，用于避免仅凭价格或速度放大不稳定渠道。

保存后，新进入且未固定渠道的请求会立即使用新占比。

## 5. 配置访问令牌

进入“访问令牌”，点击新增令牌并设置名称、启用状态和可访问模型。

- 允许全部模型：令牌可访问当前和后续新增的全部公开模型。
- 指定模型：令牌只能访问所选模型，适合按客户端或团队隔离。
- 完整令牌只在创建或重置后显示一次，应立即存入客户端的安全配置。
- 停用令牌会阻止后续调用，但不会删除既有日志和统计。

不要把完整令牌写入代码仓库、截图、日志或聊天记录。怀疑泄露时应立即重置令牌，并更新所有使用该令牌的客户端。

## 6. 连接客户端

进入“运行总览”，展开“Codex 快速开始”。先选择已经就绪的公开模型，确认服务地址指向当前网关的 `/v1` 接口。

### 6.1 复制配置

点击“复制配置”，把生成的供应商配置写入客户端配置文件，并把访问令牌配置到客户端认证文件。复制配置适用于从其他电脑访问网关的情况。

### 6.2 一键配置本机 Codex

只有浏览器和网关运行在同一台机器，且控制台通过回环地址打开时，页面才显示“一键配置本机 Codex”。

该操作会读取并更新运行账号目录下的 Codex `config.toml` 与 `auth.json`，可选择复用现有供应商或新增供应商，并可复用现有访问令牌或创建新令牌。保存前应核对模型、服务地址、供应商标识和令牌方式。

从其他电脑访问控制台时，请使用“复制配置”手动配置访问者电脑，不要尝试写入网关运行机的本地文件。

## 7. 验证首次调用

完成渠道、模型和令牌配置后，从客户端发起一个短请求，然后进入“调用日志”。

核对以下信息：

- HTTP 状态和业务结果为成功。
- 请求模型与预期公开模型一致。
- 实际渠道和上游模型正确。
- 输入、输出、缓存 Token 和费用出现合理数值。
- 流式请求存在首 Token 样本。
- 路由决策中选中候选、概率和评分符合当前配置。

失败时打开请求详情，按上游尝试时间线查看重试、切换渠道、熔断和错误原因。

## 8. 日常运营页面

### 8.1 运行总览

运行总览按所选自然日范围汇总请求量、成功情况、Token、费用、响应时间和渠道分布。切换时间范围时，趋势会在小时与天维度之间调整。

### 8.2 调用日志

调用日志适合定位单次请求。可按模型、渠道、令牌、结果和时间范围筛选。详情中包含公共请求、上游尝试、路由选择、用量、费用、响应时间以及按系统设置保留的请求和响应正文。

### 8.3 会话日志

会话日志按客户端会话聚合历史调用，用于观察一个会话内的模型、渠道、请求量、成功率、费用和响应表现。打开会话详情可查看连续请求轨迹。

### 8.4 活跃会话

活跃会话只展示最近 30 分钟仍有调用的用户会话，并按最近活跃时间排序。可按会话名称或会话 ID 搜索，点击行进入会话详情。

## 9. 处理熔断记录

“熔断记录”按“渠道 → 模型 → 熔断事件”展示，先定位受影响渠道，再查看具体模型的事件序列。

- 一级、二级熔断通常会在截止时间后进入恢复探测。
- 三级熔断会停用对应模型映射，等待管理员处理。
- 已恢复事件会显示恢复时间和恢复方式。
- 失败原因保留上游返回的诊断摘要，可用于检查账号、密钥、额度、模型权限或网络。

对待人工开启的三级记录，先修复上游问题，再点击该事件右侧的人工开启操作。开启后映射会重新参与调度；如果根因未消除，后续请求可能再次触发熔断。

## 10. 系统设置

系统设置包括以下内容：

- 服务监听：主机和端口变更需要重启进程后生效。
- 路由决策：设置价格、效率、质量和均衡占比。
- 请求与重试：设置最大尝试次数、请求体上限、响应头等待和流式空闲超时。
- 会话与数据：设置管理会话时长、Cookie 安全属性、调用日志记录细节和首次渠道配置的常用模型。
- 日志参数清理：清空指定时间前的请求参数和正文，同时保留状态、Token、费用与耗时统计。

修改前记录原值。与监听、Cookie 或日志明细有关的配置会影响访问方式、安全边界或磁盘占用，应在明确影响后再保存。

## 11. 常见问题

### 11.1 模型没有可路由渠道

检查公开模型是否启用、渠道是否启用、模型映射是否启用，以及渠道是否处于熔断状态。然后核对令牌是否允许访问该模型。

### 11.2 请求持续失败或频繁切换渠道

先在调用日志中查看最早的上游错误，再到熔断记录确认是否存在连续失败。重点检查上游地址、密钥、账号余额、模型权限、请求格式和运行机网络。

### 11.3 看不到一键配置按钮

一键配置只在运行机本地通过回环地址访问时显示。远程访问属于正常场景，请使用复制配置并在客户端电脑上手动写入配置。

### 11.4 修改路由占比后没有影响当前会话

已有会话可能受会话亲和或响应亲和约束，继续使用已固定的渠道。新建会话或等待固定条件解除后，再观察新的概率路由结果。

### 11.5 调用日志没有请求或响应正文

检查系统设置中的日志记录细节。选择“摘要”只保留缩减内容，选择“无”只保留状态、用量、费用、耗时和路由结果。历史正文也可能已被管理员清理。

## 12. 安全与维护建议

- 控制台只向受信任网络和管理员开放。
- 生产环境使用 HTTPS，并启用仅 HTTPS 发送的安全 Cookie。
- 为不同客户端签发独立令牌，按需要限制模型范围。
- 定期轮换上游密钥和客户端令牌。
- 根据磁盘容量选择日志正文记录级别，并定期检查占用。
- 变更路由占比、重试或超时后，通过调用日志验证实际结果。
- 升级版本后检查本手册的适用版本和更新日期。
